# UI Design Workbench

[English (основной README)](README.md)

UI Design Workbench превращает UI-код проекта в автономный интерактивный HTML-workbench. Он находит экраны, переходы, компоненты, темы и состояния без запуска приложения, сборки, dev server, эмулятора или симулятора.

```text
UI проекта → кешированная карта → строгий ui-ir.json → интерактивный ui-preview.html
```

CLI не зависит от конкретного AI. В комплекте есть Agent Skill для Codex, Claude Code, Cursor, Gemini CLI, Copilot CLI, OpenCode и других локальных агентов с доступом к файлам и shell.

## Зачем нужен этот инструмент

Обычно AI начинает UI-задачу с нескольких найденных файлов или скриншотов. Он может не заметить скрытые экраны, повторно сканировать проект в следующих задачах, добавить неподтверждённые стили или изменить рабочий код до того, как пользователь увидит результат. Для проверки переходов часто приходится запускать приложение или вручную собирать набор скриншотов.

UI Design Workbench добавляет детерминированный слой между исходным кодом и решениями AI:

| Обычная работа без workbench | С UI Design Workbench |
| --- | --- |
| AI читает первые найденные UI-файлы | Сканер строит повторно используемую карту экранов, маршрутов, компонентов, токенов, тем и состояний |
| Скрытые маршруты, вкладки, drawer или экраны админки могут быть пропущены | Каждый найденный экран один раз включается в иерархическое дерево |
| Интерфейс воссоздаётся по памяти AI или стандартными HTML-контролами | Макет строится из строгого IR с привязками к исходникам и токенам проекта |
| Для просмотра переходов нужен запуск приложения, эмулятора или dev server | Автономный HTML показывает экраны и объявленные переходы без запуска приложения |
| В следующих задачах проект сканируется заново | Кеш по хешам обновляет только изменённые UI-файлы |
| Реконструкция может смешиваться с непрошеными советами по редизайну | Проверка переноса и UI/UX-ревью разделены на разные явные операции |
| Исходники могут измениться до визуального согласования | Сначала создаётся предложение в workbench; для правки проекта нужно отдельное разрешение |
| Before/After и комментарии распределены по чату и скриншотам | Версии, сравнение, проблемы и привязанные комментарии находятся в одном артефакте |
| Платформенные правила зависят от текущего промпта | Опциональные профили дают единые правила Android, iOS, macOS, Windows, Flutter и Web |

Инструмент полезен, когда нужно разобраться в незнакомом UI-проекте, увидеть все экраны без запуска приложения, получить интерактивный макет, безопасно сравнить редизайн или провести отдельное платформенное ревью. Он не заменяет финальное тестирование в настоящем приложении.

## Важно

- `uidw workbench` и `uidw check` проверяют только точность реконструкции и работу HTML. Они не оценивают UI/UX продукта и не создают замечания.
- Только `uidw review` запускает UI/UX-аудит. Используйте его лишь по явному запросу на ревью.
- Рендеринг, ревью и предложения не изменяют исходники приложения.
- Для изменения проекта требуется отдельное разрешённое apply-задание.
- Сгенерированный HTML работает без локального сервера.
- Состояние ревью привязано к версии макета и явно сохраняется/восстанавливается через меню «Файл»; открытие и проверка preview ничего не скачивают автоматически.
- Runtime findings версионируются вместе с diagnostics engine и заменяются при повторной проверке, поэтому исправленные проверки не остаются старыми проблемами.

## Возможности

- Полный список экранов и маршрутов с иерархическим деревом.
- Интерактивные переходы через реконструированные элементы интерфейса.
- Режимы всех экранов, прототипа, одного экрана, вариантов и отдельного сравнения.
- Отдельные dropdown-поля темы и состояния; светлая, тёмная и пользовательские темы добавляются только при наличии в коде.
- Детерминированные мок-данные, включая повторяющиеся элементы списков, таблиц и сеток.
- Общий zoom холста, перемещение зажатым колёсиком, регулируемые панели, инспектор и привязанные комментарии.
- Опциональное UI/UX-ревью со стабильными номерами проблем и вариантами Before/After.
- Происхождение свойств до исходного файла, строгий IR, резолвер токенов и неизменяемая базовая версия.
- Профили Android, iOS, macOS, Windows, Flutter и Web.
- Инкрементальный кеш, который уменьшает повторное сканирование и расход токенов.
- Русская и английская локализация оболочки workbench.

## Требования

- Python 3.10 или новее.
- Git.
- Локальный AI-агент с доступом к файлам и shell.
- Необязательно: Node.js и Chrome, Edge либо Chromium для headless-проверок HTML.
- Необязательно: Pillow для pixel regression.

Среда выполнения и SDK целевого приложения для построения макетов не нужны.

## Установка

Сначала клонируйте репозиторий:

```sh
git clone https://github.com/Elgreed/ui-design-workbench.git
cd ui-design-workbench
```

### Windows 10/11

```powershell
py -m pip install --user pipx
py -m pipx ensurepath
py -m pipx install .
.\install.ps1 -Agent codex
```

Вместо `codex` можно указать `claude`, `cursor`, `gemini`, `copilot`, `opencode`, `agents` или `all`.

Если PowerShell блокирует установщик:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Agent codex
```

### macOS и Linux

```sh
python3 -m pip install --user pipx
python3 -m pipx ensurepath
python3 -m pipx install .
sh ./install.sh codex
```

Вместо `codex` укажите нужного агента или `all`.

Перезапустите агента или откройте новую сессию, затем проверьте установку:

```sh
uidw --version
uidw --json doctor
```

Без установки используйте `python scripts/uidw.py` в Windows или `python3 scripts/uidw.py` в macOS/Linux.

## Быстрый старт

### 1. Выберите детализацию макета

```sh
uidw --repo <repo> config setup
```

| Уровень | Что входит |
| --- | --- |
| `low` | Экраны, базовая разметка, минимальные мок-данные |
| `medium` | Low плюс переходы, взаимодействия, нужные состояния и репрезентативные данные |
| `high` | Medium плюс расширенные данные, найденные темы, доски вариантов и полная проверка реконструкции/HTML |

Мок-данные включены всегда, но их объём зависит от уровня. Ни один уровень не запускает UI/UX-ревью.

### 2. Соберите HTML-workbench

```sh
uidw --repo <repo> workbench --output-dir <artifacts> --level full --open --view overview --lang ru
```

Первый запуск создаёт UI-индекс, граф и стартовый IR. Следующие запуски используют кеш и повторно анализируют только изменённые UI-файлы.

### 3. Откройте экран или интерактивный прототип

```sh
uidw --repo <repo> open <artifacts>/ui-preview.html --launch --view single --screen <screen-id> --lang ru
uidw --repo <repo> open <artifacts>/ui-preview.html --launch --view prototype --screen <screen-id> --lang ru
```

Workbench использует реконструированные элементы проекта и не заменяет их стандартными браузерными кнопками или input.

## Режимы просмотра

| Режим | Назначение |
| --- | --- |
| Все экраны | Все найденные экраны на одном холсте |
| Прототип | Переходы по объявленной навигации через клики |
| Один экран | Просмотр экрана без смены экрана при навигационном клике |
| Варианты | Темы, состояния или сгруппированная матрица тема × состояние |
| Сравнение | Две выбранные версии рядом или в режиме наложения |

Тема и состояние выбираются отдельными dropdown-полями. В матрице они отмечают текущую комбинацию, но не скрывают остальные варианты. Zoom изменяет макеты, а не панель управления вариантами.

## UI/UX-ревью

Запускайте ревью только когда оно действительно требуется:

```sh
uidw --repo <repo> review --output-dir <review-dir> --level full --lang ru
```

Процесс ревью:

1. Запустить аудит.
2. Выбрать проблемы для исправления.
3. Создать один сдержанный вариант или два, если есть реальный UX-компромисс.
4. Сравнить неизменяемую версию Before с предложением.
5. Подтвердить новый макет.
6. Подготовить apply-задание для реального проекта.
7. После внедрения выполнить целевую проверку.

Замечания всегда привязаны к неизменяемой проверенной версии. Предложение может отметить решённые проблемы, но окончательно проблема закрывается только после успешной проверки изменений в проекте.

Для переносимой резервной копии используйте `Сохранить ревью` и `Восстановить ревью` в меню «Файл». Хранилище браузера автоматически восстанавливает неизменённое ревью, а несовместимая техническая диагностика пересчитывается без потери решений и комментариев.

CLI создаёт переносимые задания для AI, но сам не запускает провайдера и скрыто не изменяет исходники.

Полезные команды:

```sh
uidw findings list --ir <review-dir>/ui-ir.json
uidw findings accept 7 25 --ir <review-dir>/ui-ir.json
uidw proposal prepare --ir <review-dir>/ui-ir.json
uidw apply prepare --ir <review-dir>/ui-ir.json
uidw apply prepare --direct --ir <review-dir>/ui-ir.json
```

`--direct` — явный быстрый путь без предварительного подтверждения нового макета.

## Кеш и экономия токенов

Ручной `init` необязателен. Команды `context`, `workbench` и `review` сами создают кеш при необходимости.

```sh
uidw --repo <repo> status
uidw --repo <repo> sync
uidw --repo <repo> diff
uidw --repo <repo> context --screen <screen-id> --budget 4000
```

По умолчанию производные данные хранятся в пользовательском кеше ОС, а не в проекте или установленном навыке. Хеши содержимого инвалидируют только изменённые UI-файлы. Для другого каталога задайте `UIDW_CACHE_HOME`.

Для больших ревью не нужно загружать агенту весь IR. `scope` создаёт структурно полный контекст только для выбранных экранов и замечаний, а `patch` принимает только разреженные операции с findings, proposal-версиями, аннотациями и результатами проверки. Замена базового UI через патч запрещена.

```sh
uidw --repo <repo> scope --ir <review-dir>/ui-ir.json --screen <screen-id> --budget 4000
uidw --repo <repo> patch template --ir <review-dir>/ui-ir.json --context <review-dir>/ui-agent-context.json
uidw --repo <repo> patch validate <review-dir>/ui-ir.patch.json --ir <review-dir>/ui-ir.json
uidw --repo <repo> patch apply <review-dir>/ui-ir.patch.json --ir <review-dir>/ui-ir.json --output <review-dir>/ui-ir.proposed.json
```

Необязательный локальный MCP предоставляет те же ограниченные операции через `stdio`, без порта и сетевого сервера. Установите дополнение командой `pip install ".[mcp]"`, затем запустите `uidw-mcp --repo <repo>` или `uidw --repo <repo> mcp`. Обычный CLI не зависит от MCP и остаётся полноценным fallback.

## Опциональные платформенные правила

Режим платформенных правил для обычных UI-задач по умолчанию выключен:

```sh
uidw --repo <repo> ui-mode --enable
uidw --repo <repo> ui-mode --disable
```

После включения агент использует компоненты проекта и правила обнаруженной платформы только при реализации запрошенного изменения. Он не сканирует остальной UI и не запускает ревью автоматически.

## Fidelity Core

Fidelity Core делает доказательства реконструкции доступными для проверки:

```sh
uidw fidelity capabilities
uidw fidelity report --ir <artifacts>/ui-ir.json
uidw fidelity explain <node-id-or-evidence-id> --ir <artifacts>/ui-ir.json
```

Встроенные адаптеры поддерживают HTML/CSS, React/JSX, Vue, Svelte, Jetpack Compose, Android Views XML, SwiftUI, Storyboard/XIB, WinUI/WPF XAML и Flutter. Неподдерживаемый синтаксис явно указывается и не заменяется придуманным UI.

Адаптеры Android и Apple переносят структуру, но не являются нативными рендерами. Доступный точный путь можно проверить без запуска сборки или симулятора:

```sh
uidw --repo <repo> native status
```

Для MCP та же ограниченная операция называется `ui_native_status`. Android-discovery распознаёт Compose Screenshot, Paparazzi, Roborazzi и готовность эмулятора. Apple-discovery распознаёт Xcode Preview, snapshot-тесты и готовность симулятора; для нативного Apple-снимка всегда нужен macOS-воркер с Xcode. Нативное состояние кешируется отдельно от базового IR, а снимок становится устаревшим после изменения исходников.

Встроенный структурный Android-рендер разрешает исходные `strings`, `colors`, `dimens`, наследуемые стили, bitmap/vector/shape drawables и статические layout includes. Для Compose переносятся основные size/padding/fill/weight/alignment/typography modifiers и ограниченный набор Material icons. Сложные constraints, custom drawing, runtime-темы и неизвестные иконки остаются явными gaps, а не получают незаметные browser defaults.

Для Flutter и React Native необходимо указать целевую платформу перед платформенными UX-выводами.

## Основные команды

| Команда | Назначение |
| --- | --- |
| `uidw doctor` | Проверить установку и необязательные зависимости |
| `uidw --repo <repo> context --json` | Получить компактный кешированный контекст |
| `uidw --repo <repo> scope ...` | Создать ограниченный контекст экрана/замечаний для агента |
| `uidw --repo <repo> patch ...` | Проверить или применить разреженные операции IR |
| `uidw --repo <repo> workbench ...` | Собрать и проверить HTML-проекцию |
| `uidw --repo <repo> native status` | Найти нативные Android/Apple-провайдеры без их запуска |
| `uidw --repo <repo> check --ir <file> --level full` | Повторить проверки переноса без UI/UX-аудита |
| `uidw --repo <repo> review ...` | Явно запустить UI/UX-ревью |
| `uidw --repo <repo> scenarios validate --ir <file>` | Проверить сценарии и наполненные коллекции |
| `uidw pack --ir <file> --output review.uidw.zip` | Создать переносимый пакет |
| `uidw unpack review.uidw.zip --output-dir <dir>` | Распаковать пакет |
| `uidw help config` | Открыть справку по настройкам |
| `uidw help advanced` | Показать расширенные команды |

```text

Не изменяй исходники, если apply-задание явно не содержит sourceChangeAllowed: true.
```
