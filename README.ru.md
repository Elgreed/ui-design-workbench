# UI Design Workbench

[English](README.md) | **Русский**

UI Design Workbench — навык Codex для реконструкции, генерации, редизайна и глубокого UI/UX-ревью интерфейсов непосредственно по исходному коду проекта.

Он создаёт отдельный интерактивный HTML-workbench без запуска целевого приложения, эмулятора, симулятора или dev-сервера. Workbench сохраняет подтверждённые кодом особенности интерфейса, показывает дерево экранов и переходы, поддерживает комментарии и варианты Before/After и не изменяет исходный проект до отдельного подтверждения внедрения.

## Для чего нужен инструмент

Обычные design-to-code инструменты начинают работу с готового дизайн-макета. UI Design Workbench поддерживает и обратное направление: находит уже реализованный в репозитории UI и превращает его в удобное пространство для просмотра и проектирования.

Инструмент позволяет:

- изучать существующий UI без запуска приложения;
- создавать интерактивную карту найденных экранов и переходов;
- проверять UI и UX по стандартам проекта и целевой платформы;
- оставлять комментарии на конкретных элементах;
- генерировать новые экраны и альтернативные UI-решения;
- переделывать выбранные экраны, не затрагивая остальное поведение;
- сравнивать неизменяемый текущий дизайн с несколькими вариантами;
- согласовывать макет до изменения исходного кода.

## Поддерживаемые платформы

- Android и Jetpack Compose;
- iOS, iPadOS, UIKit и SwiftUI;
- Web-приложения;
- React Native;
- Flutter.

Workbench использует соответствующую платформенную основу: Material для Android, Apple Human Interface Guidelines для платформ Apple, а для Web — семантический HTML, WCAG и паттерны ARIA APG. Если в проекте найдены собственные компоненты и дизайн-токены, они имеют приоритет.

## Основные возможности

- **Поиск UI в репозитории** — экраны, маршруты, навигация, компоненты, токены, типографика и ресурсы.
- **Дерево экранов** — каждый переведённый экран отображается один раз в компактной иерархии с поиском.
- **Несколько режимов холста** — все экраны, прототип, отдельный экран и сравнение Before/After.
- **Интерактивный прототип** — воспроизводит найденные переходы и локальные состояния компонентов.
- **Инспектор и комментарии** — связывает обратную связь с экраном, узлом, версией и исходным кодом.
- **Глубокое UI/UX-ревью** — анализирует иерархию, отступы, типографику, состояния, понятность, плотность, доступность, иконки, адаптивность и взаимодействия контролов.
- **Детерминированная диагностика** — проверяет зум, пересечения, обрезку, геометрию, меню, навигацию, размеры целей, контраст, accessible names и заявленные состояния.
- **Процесс исправления** — преобразует выбранные проблемы в отдельные proposal-версии, не заменяя baseline.
- **Передача в Codex** — открывает подготовленную локальную задачу через официальный `codex://new` deep link без bridge-сервера и открытого порта.
- **Защита исходников** — принятие макета само по себе не разрешает изменения в репозитории приложения.

## Установка

Клонируйте репозиторий в каталог навыков Codex.

### Windows PowerShell

```powershell
git clone https://github.com/Elgreed/ui-design-workbench.git "$env:USERPROFILE\.codex\skills\ui-design-workbench"
```

### macOS или Linux

```bash
git clone https://github.com/Elgreed/ui-design-workbench.git ~/.codex/skills/ui-design-workbench
```

После установки перезапустите Codex или откройте новую задачу, чтобы навык был обнаружен заново.

## Быстрый старт

Откройте нужный репозиторий в Codex и вызовите навык явно:

```text
$ui-design-workbench найди UI в этом проекте и собери интерактивный HTML-workbench
```

Другие примеры:

```text
$ui-design-workbench проведи ревью собранного UI и покажи исправленные варианты Before/After
```

```text
$ui-design-workbench переделай экран настроек, сохранив дизайн-систему проекта
```

```text
$ui-design-workbench создай новый onboarding flow по стандартам целевой платформы
```

Навык также может выбираться автоматически для подходящих запросов на реконструкцию, проектирование, редизайн или ревью UI.

## Режимы работы

### Reconstruct

Воссоздаёт интерфейс, уже существующий в исходном коде. Главные приоритеты — точность и происхождение элементов; творческие изменения не добавляются.

### Generate

Создаёт новые интерфейсы по задаче, компонентам и токенам проекта и стандартам выбранной платформы.

### Redesign

Исправляет обозначенные UX-проблемы, сохраняя несвязанное поведение и неизменяемый baseline текущего дизайна.

### Review

Собирает текущий UI как baseline, выполняет детерминированный и экспертный анализ, создаёт обоснованные findings и предлагает исправленные версии.

## Типичный процесс

1. Codex сканирует репозиторий и находит UI entry points, экраны, маршруты, навигацию, компоненты, токены и ресурсы.
2. Формирует `ui-ir.json` — переносимое представление интерфейса и состояния ревью.
3. Генерирует автономный `ui-preview.html` вне исходного репозитория по умолчанию.
4. Выполняет проверки покрытия, платформенного профиля, взаимодействий, геометрии и доступности.
5. Пользователь перемещается между экранами, изучает элементы, оставляет комментарии и выбирает проблемы.
6. Codex создаёт отдельные proposal-версии и сравнение Before/After.
7. Пользователь принимает вариант, отклоняет его или запрашивает следующую итерацию.
8. Только после принятия дизайна Codex может подготовить отдельный план внедрения и предлагаемый diff исходников.

## Работа с собранным workbench

- **Все экраны** показывает все переведённые экраны на одном общем холсте.
- **Прототип** включает переходы между экранами и историю браузера.
- **Отдельный экран** блокирует навигацию для внимательного просмотра.
- **Сравнение** показывает любые две сохранённые версии рядом или наложением.
- **Клики** управляет контролами и переходами прототипа.
- **Свойства** показывает узел, компонент, источник, семантику, платформенный стандарт и уровень точности.
- **Комментарии** привязывает отзыв к выбранному узлу и версии.
- **Ревью** запускает диагностику, показывает проблемы, управляет очередью исправлений и согласованием.

Навигация по экранам находится в левой панели. Свойства, findings и комментарии разделены на вкладки правой панели. Обе панели можно скрывать и изменять по ширине. Зум холста не изменяет размеры экранов и управляется компактным блоком справа внизу или колесом мыши над холстом.

## Ревью и исправления

1. Откройте вкладку **Ревью** и выберите область проверки.
2. Запустите **Ревью макетов**, чтобы проверить выбранные экраны и viewport-профили.
3. В разделе **Проблемы** отметьте findings как «В исправление», «Не исправлять» или «Позже».
4. Откройте **Изменения** и создайте вариант для выбранных проблем.
5. Откроется подготовленная задача Codex с каталогом макета как рабочей областью. Просмотрите и отправьте готовый запрос.
6. Когда Codex пересоберёт файлы, вернитесь в workbench и обновите его.
7. Сравните предложение с baseline и примите его или запросите ещё одну итерацию.

Deep link только подготавливает задачу. Он не отправляет запрос и не заявляет, что AI уже начал работу. Копирование запроса и JSON-задания остаются резервными способами передачи.

## Создаваемые файлы

Полный пакет ревью может содержать:

- `ui-scan.json` — найденные UI-элементы и структура проекта;
- `ui-ir.json` — экраны, узлы, компоненты, действия, версии, findings и provenance;
- `ui-preview.html` — автономный интерактивный workbench;
- `platform-profile-report.json` — проверка платформенных стандартов;
- `ui-coverage.json` и `ui-coverage.md` — покрытие перевода и доказательств;
- `ui-interaction-matrix.json` — сценарии состояний и взаимодействия контролов;
- `ui-diagnostics.json` — выполненные проверки workbench;
- скриншоты и снимки DOM-геометрии;
- JSON с обратной связью, заданиями на исправление и планом внедрения.

По умолчанию файлы ревью хранятся отдельно от репозитория приложения.

## Границы безопасности и точности

- Целевое приложение не запускается без отдельного запроса пользователя.
- Уровень точности реконструкции определяется доступными доказательствами в исходном коде.
- Стандартные браузерные контролы не должны незаметно заменять компоненты проекта.
- Отсутствующие ресурсы и неподдерживаемые конструкции отмечаются явно, а не придумываются.
- Baseline неизменяем; предложения хранятся отдельными sparse-версиями.
- Принятие дизайна не является разрешением на изменение исходников.
- Перед изменением перечисленных файлов и diff требуется отдельное подтверждение.

## Требования

- Codex с поддержкой локальных навыков;
- Python 3.10 или новее;
- Node.js для headless smoke-проверок;
- Chrome, Edge или Chromium для браузерной диагностики, скриншотов и проверки геометрии.

Для построения workbench не требуются runtime целевого приложения, эмулятор, симулятор, bridge-сервер, localhost-сервис или сетевой dev-сервер.

## Структура репозитория

```text
ui-design-workbench/
├── SKILL.md              Точка входа и рабочий контракт навыка
├── agents/openai.yaml    UI-метаданные Codex и стандартный запрос
├── references/           Платформенные правила, схемы, точность и ревью
└── scripts/              Сканер, renderer, валидаторы и диагностика
```

Полный рабочий процесс и инварианты находятся в [SKILL.md](SKILL.md). Схемы и стандарты — в [`references/`](references/), детерминированные инструменты — в [`scripts/`](scripts/).
